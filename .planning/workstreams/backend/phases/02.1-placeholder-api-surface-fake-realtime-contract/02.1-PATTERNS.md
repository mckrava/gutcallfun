
### Shutdown / cleanup pattern — MANDATORY for `fake-cycle.service.ts`

**Analog:** `src/modules/ingest/stream/stream-manager.service.ts` (lines 1-104, read above).
This is Phase 2's `OnApplicationShutdown` implementation and is the closest and most important
precedent for the new gateway's timer teardown, per the phase brief's explicit instruction.

```typescript
@Injectable()
export class StreamManagerService implements OnApplicationShutdown {
  private readonly controllers = new Map<number, AbortController>();

  start(gameId: number): void {
    if (this.controllers.has(gameId)) { /* no-op guard */ return; }
    const controller = new AbortController();
    this.controllers.set(gameId, controller);

    void this.runConnection(gameId, controller.signal, false).finally(() => {
      if (this.controllers.get(gameId) === controller) {
        this.controllers.delete(gameId);
      }
    });
  }

  stop(gameId: number): void {
    const controller = this.controllers.get(gameId);
    if (!controller) return;
    controller.abort();
    this.controllers.delete(gameId);
  }

  async onApplicationShutdown(): Promise<void> {
    for (const controller of this.controllers.values()) {
      controller.abort();
    }
    this.controllers.clear();
  }
}
```

**Copy the shape:** a keyed map (`Map<key, handle>`), an idempotent `start()` with a
duplicate-guard, an explicit `stop()` that both aborts/clears the handle AND deletes the map
entry, and a shutdown hook that iterates and clears everything. This maps directly onto
`fake-cycle.service.ts`'s `startCycleForRoom`/`stopCycleForRoom`/`onModuleDestroy` triad in
RESEARCH.md Pattern 3.

**Do NOT copy this specific line — documented hazard:**
```typescript
void this.runConnection(gameId, controller.signal, false).finally(() => { ... });
```
`void <promise>.finally()` runs the cleanup callback but **does not catch a rejection** from the
awaited promise — an unhandled promise rejection can still surface if `runConnection` rejects,
because `.finally()` only observes settlement, it does not consume the rejection. This exact
hazard is the subject of the pre-existing open item at
`.planning/todos/pending/stream-abort-unhandled-rejection-and-e2e-open-handles.md` (confirmed by
research). The fake-cycle service's `setInterval`/`setTimeout` callbacks in RESEARCH.md Pattern 3
are synchronous void functions (not promise-returning), so this specific hazard does not
directly recur there — but if any executor makes an emit callback `async` (e.g. to await a
future real data source in Phase 5), it MUST NOT copy the bare `void promise.finally()` shape;
use `.catch()` explicitly (as `source-scheduler.service.ts` line 88 does:
`this.replayStarter.start(game.id).catch((err) => this.logger.error(...))`) instead.

**Also note:** `OnApplicationShutdown` (used by `stream-manager.service.ts`) vs
`OnModuleDestroy` (recommended by RESEARCH.md Pattern 3 for `fake-cycle.service.ts`) are
different NestJS lifecycle hooks — both work with `app.enableShutdownHooks()` (already active in
`main.ts`), but `OnModuleDestroy` fires earlier (module teardown) vs `OnApplicationShutdown`
(whole-app teardown, receives the shutdown signal string). Either is acceptable per research;
`OnModuleDestroy` is the one already prescribed and is fine to use as-is.

### Config — `WEB_APP_ORIGIN` env var addition

**Analog:** `src/config/app-config.schema.ts` itself (full file, 56 lines, read above) — extend
the existing `EnvironmentVariables` class using the exact same decorator style already used for
`DATABASE_URL`:
```typescript
@IsUrl({ protocols: ['postgresql', 'postgres'], require_tld: false, require_protocol: true })
DATABASE_URL: string;
```
**New field to add, same pattern:**
```typescript
@IsUrl({ require_tld: false, require_protocol: true })
WEB_APP_ORIGIN: string;
```
No default (per research A1 — fail-fast on correctness-critical config, matching how
`DATABASE_URL`/`TXLINE_GUEST_JWT`/`TXLINE_API_TOKEN` have no defaults in this same file; contrast
with `PORT`/`NODE_ENV`/`PAST_FIXTURES_COUNT`, which DO have `@IsOptional()` + a default value —
that pattern applies to genuinely-optional config, not this one).

**Consumption pattern** — read via injected `ConfigService`, never bare `process.env`, matching
`fixtures-cron.service.ts` line 26: `this.config.get<number>('PAST_FIXTURES_COUNT') ?? 20;` and
`source-scheduler...` constructor DI style. `main.ts`'s new CORS line should do
`app.get(ConfigService).get<string>('WEB_APP_ORIGIN')`, per RESEARCH.md Pattern 4. Note research's
own documented exception: the `@WebSocketGateway({ cors: ... })` decorator option is evaluated
before DI is available, so it is the one deliberate, explicitly-commented exception that reads
`process.env.WEB_APP_ORIGIN` directly (already validated fail-fast at boot by this same schema
before any gateway can be instantiated) — do not treat this as license to bypass `ConfigService`
elsewhere.

**Registration analog** (unchanged, no new file needed) —
`src/config/config.module.ts` (full file, 10 lines, read above):
```typescript
@Global()
@Module({
  imports: [ConfigModule.forRoot({ isGlobal: true, validate })],
  exports: [ConfigModule],
})
export class AppConfigModule {}
```
No modification needed here — `validate()` (in `app-config.schema.ts`) already runs against the
full `EnvironmentVariables` class, so adding `WEB_APP_ORIGIN` to that class is sufficient.

### `src/main.ts` — bootstrap modification baseline

**Current full contents** (9 lines, this IS the modification baseline — capture exactly):

```typescript
import { NestFactory } from '@nestjs/core';

async function bootstrap() {
```
