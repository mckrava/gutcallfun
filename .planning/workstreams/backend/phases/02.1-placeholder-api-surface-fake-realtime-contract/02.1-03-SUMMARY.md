## Decisions Made

- **GAMES_FIXTURE omits a `cancelled` game** — the must_haves truths and Task 2 acceptance criteria both require `GET /games?status=cancelled` to prove the empty-filter edge case (HTTP 200, empty `items`, `total` 0), which is only true if no cancelled fixture exists. Prioritized this doubly-stated, directly-testable requirement over Task 1's more general "covering every game_status value" prose.
- **`AnswersService.create()` resolves `game_id` from `GAME_QUESTIONS_FIXTURE`** — `CreateAnswerDto` only carries `game_question_id`; `game_id` is denormalized on `user_game_answer` for the leaderboard SUM, so the service derives it via a fixture lookup rather than hardcoding a value.
- **`LeaderboardEntryDto`'s `rank` is never stored on the fixture** — a dedicated `LeaderboardFixtureEntry` type (`Omit<LeaderboardEntryDto, 'rank'>`) types the raw fixture; the service assigns `rank` from the fixture's fixed descending order on every call, so there is exactly one source of truth for both content and ordering.
- **`LEADERBOARD_FIXTURE` does not import `users.fixtures.ts`** (owned by the concurrent 02.1-02 plan) — reuses `USER_A_ID`/`USER_B_ID` from `games.fixtures.ts` plus three additional fixed literals, documented as a later-phase cross-fixture alignment concern rather than a cross-plan import.
