<flagged_assumptions>
- **OpenAPI path ordering is a backstop, not an explicit criterion.** `@nestjs/swagger` builds the
  `paths` object from decorator metadata discovery order, which is stable in practice but is not a
  documented contract. The must-have is recorded as a backstop marker rather than a hard assertion
  because a future NestJS patch could reorder it without that constituting a real contract break —
  a client must key off path strings, never off object ordering.
- **Question-cadence timing in e2e.** The 30-second question period makes a full real-time cycle
  assertion expensive in e2e. The question-to-resolution correlation is asserted in plan 04's unit
  spec under fake timers instead; this plan's e2e asserts the snapshot and the 4-second heartbeat
  only. That is a deliberate trade of e2e fidelity for suite runtime, recorded rather than hidden.
</flagged_assumptions>
