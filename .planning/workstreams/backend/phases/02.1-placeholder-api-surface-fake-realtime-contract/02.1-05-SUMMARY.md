## Decisions Made

- **Data-hygiene fix over source-code fix for the stale 'live' DB row** (see Deviations for full detail): chosen specifically because it stays inside the "don't touch ingest source" boundary while eliminating the actual trigger, rather than reinterpreting away a failure that was genuinely fixable.
- **Schema-uniqueness assertion by count equality, not containment**: `expect(knownSchemaKeys).toHaveLength(EXPECTED_SCHEMA_NAMES.length)` after filtering `components.schemas` keys down to the known set — a real name collision merges two classes into one schema key, which only an equality check (not a `toContain` loop) would catch.
- **`git diff` gate re-scoped from `origin/develop` to this plan's own wave base commit**: `origin/develop` predates this entire phase's merge (confirmed via `git log`), so the plan's literal acceptance-criterion command would report the whole pre-existing Phase 2 ingest tree as "changed" regardless of anything this plan did. Diffing against `c38db2aa9151...` (this worktree's actual base) is the comparison that answers the real question and correctly returns 0.
- **Response-body typing in e2e specs via local minimal interfaces + `as Shape` casts**, not raw `any` access — matches this repo's `no-unsafe-*` eslint enforcement on `test/**/*.ts` (confirmed via `npm run lint`'s glob and by checking the pre-existing `ingest-pipeline.e2e-spec.ts`, which is itself lint-clean).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking, environmental] Stale 'live' DB row triggered a Phase-2 unhandled-abort crash in every new e2e spec that calls `app.close()`**
- **Found during:** Task 2, first run of `test/realtime.e2e-spec.ts`
- **Issue:** The worktree's shared dev Postgres had `game.id = 18` (fixture 18143850) left at `status = 'live'` from an earlier manual/dev session, with zero ingested events and `is_replay = false`. `GameStateRebuildService.onApplicationBootstrap()` (verified by direct source read, `src/modules/ingest/recovery/game-state-rebuild.service.ts`) unconditionally calls `StreamManagerService.start(18)` for *any* `status='live'`, non-replay game at boot — a real SSE reconnect attempt using the real `.env` credentials. On `app.close()`, `StreamManagerService.onApplicationShutdown()` aborts that controller, and the documented pre-existing bug (`.planning/todos/pending/stream-abort-unhandled-rejection-and-e2e-open-handles.md`, "unhandled `AbortError` when a live SSE stream is aborted") fires as an uncaught exception that kills the Jest worker process before it can report results (confirmed reproducing identically in `ingest-pipeline.e2e-spec.ts`, matching the environment notes' description exactly — same root cause, not a new bug).
- **Fix:** `UPDATE game SET status='finished', updated_at=now() WHERE id=18 AND status='live'` against the local dev Postgres (127.0.0.1:5488) — a data-hygiene action, not a source-code change. This is explicitly **not** a modification to `src/modules/ingest/**` or `src/models/**` (the plan's hard prohibition, T-02.1-29): it removes the boot-time trigger condition without touching a single line of ingest source. Confirmed via direct query that the row had zero ingested `game_event` rows and a null `stream_cursor`, consistent with being an inert leftover artifact rather than meaningful test data any other spec depends on.
- **Files modified:** None (runtime DB state only — no git diff).
- **Verification:** Re-ran `test/realtime.e2e-spec.ts` with `--detectOpenHandles`: 3/3 pass, exit 0, no crash. Re-ran the full `npm run test:e2e`: 5/5 suites, 40/40 tests, exit 0 (previously: exit 1, one file crashed with no test summary printed at all). Confirmed `ingest-pipeline.e2e-spec.ts`'s own pre-existing pass count (its 1 test) is unaffected and still green.
- **Committed in:** Not applicable — DB state change, no commit.

**2. [Rule 1 - Bug] `expect()` called with an unsupported Jasmine-style second argument**
- **Found during:** Task 2, first `test:e2e` run after writing `openapi-contract.e2e-spec.ts`
- **Issue:** Two assertions used `expect(actual, 'custom message').toBe(...)` — this Jest version's `expect()` only accepts the actual value (no second custom-message argument), so both threw `Expect takes at most one argument` at runtime, failing both tests.
- **Fix:** Rewrote the "empty responses object" assertion to throw a descriptive `Error` naming the offending route/method when the check fails (instead of a second `expect()` argument), and dropped the second argument from the integer-type spot-check assertions.
- **Files modified:** `apps/gutcallfun-core/test/openapi-contract.e2e-spec.ts`
- **Verification:** Re-ran the file in isolation: 8/8 pass.
- **Committed in:** `54d0845` (Task 2 commit — fixed before commit, not a separate commit)

**3. [Rule 1 - Bug] eslint `no-unsafe-*` violations from untyped `res.body`/socket.io event payloads**
- **Found during:** Task 2, running `npx eslint` on the three new spec files before committing (following the same discipline documented as a pitfall in `02.1-01-SUMMARY.md`/`02.1-03-SUMMARY.md`)
- **Issue:** `supertest`'s `res.body` and `socket.io-client`'s event-callback payloads are typed `any`; direct property access on them triggers `@typescript-eslint/no-unsafe-member-access`/`no-unsafe-assignment`/`no-unsafe-return` under this repo's `tseslint.configs.recommendedTypeChecked` config, and `expect.any(String)` inside `toMatchObject` triggers the same `no-unsafe-assignment` pattern already flagged in `02.1-03-SUMMARY.md`'s own deviation log.
- **Fix:** Declared minimal local response-shape interfaces (`PaginatedBody<T>`, `UserBody`, `GameBody`, `SnapshotPayload`, etc.) and cast `res.body as Shape` / typed the socket.io callback parameter directly; replaced `toMatchObject({ x: expect.any(String) })` with individual `expect(typeof x).toBe('string')` assertions.
- **Files modified:** `apps/gutcallfun-core/test/api-surface.e2e-spec.ts`, `apps/gutcallfun-core/test/realtime.e2e-spec.ts`, `apps/gutcallfun-core/test/openapi-contract.e2e-spec.ts`
- **Verification:** `npx eslint <all six files touched this plan>` exits 0 (zero errors, zero warnings); re-ran full `test:e2e` after the typing changes — still 40/40 passing.
- **Committed in:** `54d0845` (Task 2 commit — fixed before commit, not a separate commit)
