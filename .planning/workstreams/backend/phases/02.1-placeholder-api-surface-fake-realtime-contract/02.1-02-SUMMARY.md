## Decisions Made

- `findScoreProfile(squadId)` resolves by scanning that squad's participants for the first one with a non-null `score_profile`, then looking that id up in `SQUAD_SCORE_PROFILES_FIXTURE` — matches the plan's explicit instruction to resolve via the participant→profile FK direction (not a squad-keyed lookup), and is the only interpretation consistent with the fixture data (only one participant across both squads references a score profile).
- `findParticipants(squadId, query)` takes a plain `PaginationQueryDto`, not `ListSquadsQueryDto` — the latter's `participant_id` filter has no meaning once already scoped to a single squad's participant list, so reusing the narrower shared DTO avoids a meaningless optional query field on this route.
- Mock `create()`/`addParticipant()` paths use fixed literal ids/timestamps (never `Date.now()`/`crypto.randomUUID()`) to keep the spirit of D-04 intact on write-shaped mock endpoints too, even though the plan's own determinism acceptance criteria only formally test `findAll`/`findOne`.
