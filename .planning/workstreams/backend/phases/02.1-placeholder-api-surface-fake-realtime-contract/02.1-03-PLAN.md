<objective>
Freeze the game half of the client contract: the game list and detail, the seq-cursor event log,
the prediction-question shape with its four LOCKED options embedded, the join route, the static
outcome reference rows, answer submit/read, and the global leaderboard. Fourteen routes, all
returning realistically-shaped deterministic mocks whose field names match
`initial-db-structure.sql` exactly (D-01, D-04).

Purpose: this is the half the hero screen depends on. The prediction card is unrenderable without
the four options carrying `base_gain` 5/7/15/100 and a `display_order`; the live-game screen is
unrenderable without denormalized score and team names. Freezing these shapes now is what lets
Phase 4 and Phase 5 swap real logic in behind identical DTOs (D-05).

Output: six fixture modules and four resource modules (games, question-outcomes, answers,
leaderboard), Swagger-documented, fixture-backed, with unit specs.
</objective>

<flagged_assumptions>
- **GAME-03 edge probe row `unclassified` — remains UNRESOLVED.** The deterministic edge probe
  classified GAME-03 ("user can join a game, `user_game` row, optional `squad_id`") as
  `unclassified` and emitted only the generic "review manually" prompt. Per the fallback protocol
  an `unclassified` row is never auto-backstopped and never silently dropped, so it is surfaced
  here rather than converted into a must-have. The specific unresolved question is what joining
  twice should do: the composite primary key `(game_id, user_id)` makes a second join a
  constraint violation, but whether the correct client-facing behaviour is an idempotent 200, a
  409 conflict, or an upsert of `squad_id` is not decided by any source artifact. **This phase
  cannot resolve it** because nothing is persisted — the mock returns the shape unconditionally.
  Phase 5 must decide it before the route writes to the database, and that decision changes the
  documented response codes on `POST /games/:game_id/join`.
- **`reward_multiplier` and `total_points` wire type.** Postgres returns `numeric(6,3)` and
  `bigint` as strings through the `pg` driver. This phase serializes both as JSON numbers, which
  is the shape the UI should bind to. Phase 5 must coerce explicitly at the mapper boundary or the
  wire type will silently change from number to string when real persistence lands. Recorded in
  head comments on the affected fixture files.
</flagged_assumptions>
