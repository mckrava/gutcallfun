<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → REST API | First time this application accepts untrusted HTTP input from a network client. Every query param, path param, and body field crosses here. |
| npm registry → build | Five new third-party packages enter the dependency tree and execute as application code. |
| process env → app config | `WEB_APP_ORIGIN` is operator-supplied and directly determines who may call the API. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.1-01 | Information Disclosure | `app.enableCors` in `main.ts` | high | mitigate | Pass the single resolved `WEB_APP_ORIGIN` string. Wildcard, `origin: true`, and reflect-any-origin callbacks are all forbidden; acceptance criterion greps for the wildcard form and requires zero matches, and asserts the response header echoes the exact configured value. |
| T-02.1-02 | Tampering | Global `ValidationPipe` | high | mitigate | `whitelist: true` + `forbidNonWhitelisted: true` reject any property not declared on the DTO. This is the mass-assignment control that stops a client sending `wallet_address` or `id` alongside `handle` to `PATCH /users/:user_id` in plan 02. |
| T-02.1-03 | Information Disclosure | OpenAPI document served at `/api-docs-json` | high | mitigate | The document is world-readable once deployed. No credential, connection string, or TxODDS token may appear in the `DocumentBuilder` description or in any `@ApiProperty` example. Task 3 states this explicitly; the phase-wide prohibition covers logs as well. |
| T-02.1-04 | Denial of Service | `PaginationQueryDto.limit` | medium | mitigate | `@Max(100)` caps the page size so an unauthenticated caller cannot request an unbounded result set. `@Min(1)`/`@Min(0)` reject negatives that would otherwise reach a handler and throw a 500. |
| T-02.1-05 | Spoofing | Every endpoint on this surface | high | accept | D-02 means the entire API is unauthenticated and `user_id` is caller-supplied, so any client can read or write as any user. **This is acceptable ONLY because every payload is a static in-process fixture with no persistence, no real user data, and no privileged action behind it.** The moment plan-5 work puts a real repository behind any of these handlers, this becomes a critical unauthenticated-IDOR surface and the endpoints MUST NOT ship in that state without the Phase 3 session guard. Recorded as an accepted risk with a hard precondition, not as a permanent decision. |
| T-02.1-06 | Elevation of Privilege | Boot with a permissive origin | medium | mitigate | `WEB_APP_ORIGIN` has no default and no `@IsOptional()`, so a missing or malformed value crashes the process at boot rather than silently degrading to an open CORS policy. |
| T-02.1-SC | Tampering | npm installs (`@nestjs/websockets`, `@nestjs/platform-socket.io`, `@nestjs/swagger`, `socket.io`, `socket.io-client`) | high | mitigate | Package Legitimacy Gate: Task 1 is a blocking human checkpoint that precedes the install, requires publisher/repo/peer-dependency confirmation on npmjs.com for each `SUS` package, and requires confirming no `postinstall` script. Not auto-approvable. |
</threat_model>
