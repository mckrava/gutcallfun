<objective>
Port the battle-tested SSE client (`upstream.ts`) and wrap it in a NestJS stream manager that owns one authenticated live connection per live game — Last-Event-ID resume from the persisted stream_cursor, 30s idle watchdog, exponential backoff, and AbortController-based clean shutdown — feeding every message into the Plan-03 source-agnostic pipeline. StreamManagerService.start(gameId) is exposed as a callable service; the single is_replay source-switch scheduler that invokes it (for due scheduled non-replay games) lives in Plan 07 (D-02 one scheduler rule spanning both SSE and replay).

Purpose: The live-feed correctness edge cases are already solved against a 23,510-record corpus — port them, don't rebuild — and prove the live path uses the identical processEvent entry point as replay (RPLY-02).
Output: A running-per-game SSE manager exposing a callable start(gameId).
</objective>
