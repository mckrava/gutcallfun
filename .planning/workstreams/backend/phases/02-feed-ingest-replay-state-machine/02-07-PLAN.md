<objective>
Wire the source lifecycle: the single is_replay source-switch scheduler (D-02 one rule, ~15s — which also makes the manual-DB-flip demo surface work, D-06/D-08) and restart recovery — on boot, rebuild each live game's in-memory state from its own append-only game_event rows (RCVR-01), then reconnect the SSE stream from the persisted stream_cursor with Seq-gap self-heal (RCVR-02). This closes the persist-then-broadcast backbone so the pipeline survives restarts and the demo can be armed by a single DB update.

Purpose: The scheduler is what turns a scheduled game (live or manually-flipped replay) into a running source; recovery is what makes the single long-lived process durable across the deploy/restart that happens on demo day.
Output: The running orchestration — scheduler + boot recovery — that starts and resumes sources.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB game rows → scheduler | Scheduler acts on status/is_replay/starts_at; a manual DB flip is a trusted admin action |
| persisted game_event → boot rebuild | Reconstructing state from the append-only log; must not corrupt or re-write it |
| reconnect stream → pipeline | Resume boundary where seq-gap false-positives (ConnectionId reset) must be avoided |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07-01 | Tampering / data loss | boot rebuild vs append-only log | high | mitigate | Rebuild reconstructs in-memory state only; no INSERT/UPDATE/DELETE on game_event during recovery. Spec asserts no write. |
| T-02-07-02 | Repudiation / recovery-integrity | resume-from-cursor vs unpersisted event | high | mitigate | stream_cursor is never ahead of persisted events (Plan 03 same-tx invariant); on gap self-heal + GameStreamGapDetected rather than silently skipping. |
| T-02-07-03 | Denial of Service | false-positive gap storm on reconnect | medium | mitigate | ConnectionId-aware Seq comparison (Pitfall 7) — a Seq reset from a new ConnectionId is not a gap. |
| T-02-07-04 | Elevation of Privilege | manual-DB-flip demo surface | medium | mitigate | Admin/dev-only DB access; scheduler acts only on is_replay/status/starts_at, no user-facing trigger. |
</threat_model>
