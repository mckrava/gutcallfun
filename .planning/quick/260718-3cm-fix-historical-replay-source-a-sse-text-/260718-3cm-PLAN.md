<objective>
Fix historical replay (Source A) so replaying a passed game actually streams events.

Two independent defects block the same user-visible outcome:

1. **SSE-vs-JSON parse.** `GET /api/scores/historical/{fixtureId}` returns SSE-formatted
   TEXT (`data: {...}` lines), not the JSON array the OpenAPI spec claims.
   `TxlineHttpClient.doRequest` hard-codes `response.json()`, so `HistoricalClient.fetch`
   throws (`Unexpected token 'd', "data: {"Fi"... is not valid JSON`), Source A always
   returns `[]`, and the fallback to Source B is empty on a fresh DB.
2. **Missing pacing clamp.** `ReplayStarterService` never passes `maxGapMs`, so
   `emitReplay` uses its `?? Infinity` default. A real fixture's history spans ~5 days
   with a single 430,164,128 ms (4.98-day) pre-match gap between events #2 and #3 —
   the replay emits 2 events then appears frozen. `speed` does not save it (7.2 min of
   dead air even at speed=1000) and D-03 timestamp rebasing does not either (it shifts
   all timestamps by a constant delta, preserving inter-event gaps).

Purpose: restore the demoable core loop — replay a past fixture end-to-end.
Output: text-mode HTTP support, Source A wired to it, a finite caller-supplied pacing
clamp, and three new/extended test suites proving all three.
</objective>
