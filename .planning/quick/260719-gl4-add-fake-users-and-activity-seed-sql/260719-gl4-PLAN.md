# Quick Task 260719-gl4: Fake leaderboard seed

## Goal

Populate the local dev DB with 50 fake users whose points and rankings compute
correctly on every leaderboard scope (global, per-game, per-squad), so the UI
has a believable board to render.

## Key constraint discovered

`LeaderboardService` derives **all** boards at query time from
`user_game_answer.awarded_points`. `user_score_profile.total_points` is a
decorative cache nothing ranks on — the existing `scripts/seed-profiles.ts`
writes only that column and therefore moves no board. The seed must write
answer rows.

Scope requirements that follow:
- game board → needs a `user_game` row per (user, game)
- squad board → needs `squad_participant` **and** `user_game.squad_id`

## Tasks

1. Write `apps/gutcallfun-core/scripts/seed-fake-leaderboard.sql`:
   idempotent cleanup → 50 users + score profiles → eligible finished games
   discovered dynamically → squads (3 seeded + optional stuffing of real
   squad 1) → `user_game` → `user_game_answer` with points from the option's
   `base_gain` → reconcile counters → verification SELECTs.
   All randomness via md5 hashes of (user_id, question_id), never `random()`.
2. Run it against the local DB; confirm it applies cleanly.
3. Re-run it; confirm idempotency and byte-identical scores, and that the 3
   real users and their counters are untouched.

## must_haves

- truths:
  - Points are written to `user_game_answer`, not just the score-profile cache.
  - `awarded_points` is read from `game_question_option.base_gain`, never hardcoded.
  - Re-running produces identical scores (no `random()`).
  - Real users and real squad membership are never deleted or rewritten.
- artifacts:
  - `apps/gutcallfun-core/scripts/seed-fake-leaderboard.sql`
