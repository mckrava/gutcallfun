# Quick Task 260718-48a: Fix CR-01 fixtures-cron write race + CR-02 abort-signal threading Summary

**Replaced FixturesCronService's racy full-entity `save()` with a targeted `update()` over 8 cron-owned columns (CR-01), and threaded `connectWithRetry`'s `AbortSignal` into the SSE `fetch()` call and an abort-driven `reader.cancel()` (CR-02) — both `02-REVIEW.md` BLOCKER findings are now closed.**

## Accomplishments
- CR-01: `FixturesCronService.upsertAll()`'s existing-row branch now issues `this.gameRepo.update({ id }, { 8 metadata columns })` instead of loading the full entity and calling `save()` — removing the read-modify-write race with `SourceSchedulerService`'s atomic status claim and `EventIngestService`'s per-event score/cursor writes. A currently-live game re-discovered by the cron can no longer have its status/score/cursor silently reverted.
- CR-02: `SingleStreamOpts` gained a `signal` field; `runSingleStream` now passes it into the `fetchImpl` init object (transport-level abort) and registers an abort listener that calls `reader.cancel()`, interrupting a blocked read promptly rather than waiting up to 30s for the idle watchdog. The listener is released in the existing `finally` block alongside the watchdog timer clear, so nothing leaks on any exit path (normal end, thrown error including AUTH_EXPIRED, or abort).
- Corrected `stream-manager.service.ts`'s `onApplicationShutdown` doc comment, which previously asserted an invariant ("a blocked reader.read() throws immediately once its controller aborts") that was false as implemented — it now describes the real two-part mechanism (signal into fetch + abort-driven reader.cancel()).
- Reference cross-check performed and recorded: the reference port (`txodds-latency-test-app/src/upstream.ts`) has the identical gap — its own `signal` is never threaded into `fetch()` or the reader. This fix is a genuine improvement over the reference, not restored fidelity.
- New `upstream.spec.ts` proves signal-into-transport, prompt abort of a blocked read (elapsed < 1s under a 60s watchdog, unambiguously ruling out the watchdog as the cause), no watchdog-timer leak, no abort-listener leak (by handler identity, since `sleep()` registers its own listener on the same signal), and that the AUTH_EXPIRED short-circuit is intact.
- `02-UAT.md` item #2 updated with a dated note recording the fix while honestly stating the automated coverage still mocks the fetch/reader layer — `result` intentionally left `[pending]`.
